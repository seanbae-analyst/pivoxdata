# 인스타그램 카드 — 설정과 흐름

정해진 요일이 아니라 **AX에 일이 생겼을 때** 카드(1080×1350 캐러셀)와 캡션, 웹 브리핑을 만들고, **검사를 통과하면 바로 인스타그램에 올립니다.**
AX 빅 케이스는 그날 바로, 공식 발표는 일주일에 한 번 사례로, 작은 변화는 일주일치를 모아서. 올린 뒤에는 닫힌 `[게시됨]` 이슈로 기록이 남습니다.

**승인 방식으로 돌리려면** 저장소 Settings → Secrets and variables → Actions → **Variables** 탭에서
`AUTO_PUBLISH` 를 `false` 로 만드세요. 그러면 `[instagram]` 이슈가 열리고, 소유자가 `/approve` 를 달아야 올라갑니다.
Run workflow의 "테스트 초안 (승인 필요)"와, 자동 게시가 실패한 날은 늘 승인 이슈로 돌아갑니다.

**직접 만든 게시물**(예: 고정 게시물)은 `social/out/<폴더>/post.json` 을 커밋한 뒤 Actions → **instagram publish** → Run workflow 에
폴더 이름(`2026-10-25-91` 같은)을 넣으면 승인 댓글 없이 바로 올라갑니다. 같은 표식의 `[instagram]` 이슈가 열려 있으면 링크를 남기고 닫습니다.
또는 `post.json` 에 `"auto_publish": true` 를 넣어 main 에 머지하면 그대로 올라갑니다(아직 안 올린 것만, 폴더 이름 순서로 하나씩).

```
매일 10:17 KST  trends.yml   (GitHub 예약이 늦거나 빠지면 12:47 · 15:17 KST에 다시 — 그날 데이터가 이미 있으면 바로 멈춤)
  ├ 데이터 받기 → 검산 → 대시보드(/) 다시 만들기 + 변화 찾기 → trends/data/changes.json   (검산 실패 → 이슈, 아무것도 안 바꿈)
  ├ social/plan.mjs    오늘 초안을 만들까? (AX만)
  │                      · 3일 안에 잡힌, 처음 보는 AX 빅 케이스 → 점수가 가장 높은 것 하나
  │                      · 아니면 지난 AX 사건에서 6일이 지났고 안 쓴 공식 발표가 3건 이상 → 이번 주 AX 사건
  │                      · 아니면 지난 초안 뒤 7일이 지났고 작은 변화가 3개 이상 → 작은 변화 모음 (최대 5개)
  │                      · 14일 동안 아무것도 없었으면 → 요즘 숫자 묶음
  │                      · 아니면 → 사이트만 갱신하고 끝 (작은 변화는 사이트 "최근 변화"에 쌓임)
  ├ social/story.mjs   이야기(카드 글 + 캡션 + 웹 브리핑) — 공식 발표는 원문 페이지까지 읽고 사례로 (original.mjs)
  ├ social/build.mjs · render.mjs   카드 → social/out/<한국 날짜>/01.png …
  ├ social/caption.mjs 캡션 본문 다시 검사 + 브리핑 주소·출처·해시태그는 코드가 붙임
  │                      (검사를 못 넘으면 그날 초안은 지우고 사이트만 갱신 → "social: draft or briefings not made" 이슈)
  ├ social/briefs.mjs  브리핑 페이지들 (게시 전 초안은 noindex · 목록에 안 나옴)
  ├ social/commit.mjs  main에 커밋·푸시 (다른 실행과 겹쳐도 다시 받아서 5번까지) → Vercel 배포
  ├ [publish 잡] social/publish.mjs  인스타그램에 게시 → 그 브리핑을 공개(목록·RSS·홈·용어 풀이) → 닫힌 "[게시됨] …" 이슈
  │     (AUTO_PUBLISH=false · 테스트 초안 · 게시 실패일 때) "[instagram] …" 승인 이슈 → 소유자 /approve · /reject
  └ [notify 잡] social/notify.mjs  방금 공개된 브리핑을 푸시 알림으로 (보낸 것은 notified.json 에 바로 적음 — 두 번 안 감)
```

## 인스타는 AX·IT 컨설팅만 (2026-10-25)

방향과 이유는 [`CLAUDE.md`](../CLAUDE.md) · [`docs/decisions.md`](../docs/decisions.md).
인스타에는 AX 관련만 올립니다: AX 월간(Ramp AI Index) · 기업이 고르는 AI 1위 교체 · 이번 주 AX 사건(사례로) ·
조용할 땐 AX와 IT 영역 카드 묶음. 글은 "어느 IT 영역의 일이고, 도입 프로젝트에서 무엇을 확인할까" 관점으로 씁니다.
개발자 다운로드·논문·오픈 모델·설비투자·레이스 변화는 사이트 "근거 데이터"에만 둡니다(`plan.mjs` → `AX_TOPICS`).
"누가 앞서나"(`--race`, `{"post":"race"}`)는 요청해도 이유를 남기고 거절합니다. **이미 올린 게시물·브리핑은 다시 만들지 않습니다.**

## 이야기 먼저, 공식 발표는 사례로 (2026-10-26)

- **흐름은 사건 → 의미 → 실무 체크.** 큰 숫자 장(`kind=number`)은 두 장까지, AX 사건은 한 장까지(`checkSlides`). 숫자는 문장 속 근거로.
- **AX 사건 = IT 컨설팅 사례.** 발표마다 `cases[]` 하나: 누가 · 무엇을 · 어디에 · 어떻게(각 30자 이하 명사구) + IT 영역(`DOMAINS`) ·
  도입 방식(`METHODS`: 인수 · 전사 배포 · 정책·규제 · 자체 구축 · 기존 시스템에 내장 · 인프라 확장 · 파트너십 · 연구·보고서 · 투자 ·
  시범 도입 · 제품 출시) + 확인할 점(질문). 발표에 없는 칸은 "발표에 없음"(`checkCases`).
  - 카드: 사례 하나에 한 장(`kind=case`) — 머리말은 "IT 영역 · 도입 방식"(코드), 제목은 누가 무엇을, 어디에·어떻게는 코드가 두 줄 표로.
    그다음 공통 흐름 → 확인할 점(목록) → 정리. 마지막 장에 그 브리핑 주소(`data.pivoxquant.com/briefs/<폴더>`).
  - 브리핑: 사례마다 섹션 하나 — 머리에 사례 표(누가·무엇을·어디에·어떻게·확인할 점), 문단 서너 개(배경 → 어디에·어떻게 → 프로젝트에서 뜻하는 것).
    공통 흐름, "IT 컨설팅 관점"(마지막, 확인할 점은 "· " 목록). 폰에서는 사례마다 한 챕터(`사례 1`…, `공통 흐름`, `관점`).
- **원문까지 읽기** (`social/original.mjs`): 글을 쓸 때 각 발표의 공식 페이지를 읽어(그 출처의 도메인만, 리다이렉트 뒤까지 확인, 15초)
  Claude에게 발표마다 2,500자까지 줍니다. 원문은 **저장·게재하지 않습니다**. 검사에서는 출처로 쳐서, 원문의 숫자는 쓸 수 있고
  원문 문장을 24자 넘게 옮기면 거절합니다. `story.json` 에는 읽은 건수(`originals`)와 원문에서만 온 숫자(`original_numbers`, 캡션 재검사용)만 남습니다.
  못 읽은 페이지(openai.com 403 등)는 제목·요약만으로 씁니다.
- **용어도 같이** (`article.terms`): 브리핑마다 낯선 말 0~3개와 쉬운 풀이(`checkTerms`: 글에 나온 말, 아직 없는 말, 숫자 없이).
  게시가 끝나면 사이트 용어 풀이에 처음 나온 브리핑 링크와 함께 붙고(`trends/glossary.mjs`), 브리핑 본문의 그 말을 누르면 풀이가 뜹니다(`terms.js`).

## 카드는 짧게, 자세한 건 웹 브리핑

인스타 카드는 장마다 제목 + 1~2문장(140자 이하)으로 짧게 — **요약본**입니다. 같은 이야기를 Claude가 **웹 브리핑**(리드 · 섹션 3~8개 · 정리)으로
더 풀어 쓰고(`story.json` → `article`, 숫자·금지어·출처·베끼기 검사는 카드와 같음), `social/briefs.mjs`가
`/briefs/<폴더>` 페이지와 `/briefs` 목록, 홈의 "이번 주 AX 이야기"와 "지난 이야기"를 만듭니다. 카드 마지막 장과 캡션에 브리핑 주소가 붙습니다.
**브리핑은 인스타 게시가 끝나야 공개됩니다**(목록·시리즈·태그·RSS·사이트맵·홈·용어 풀이). 승인을 기다리는 초안은 캡션 링크가
바로 열리도록 페이지만 있고 noindex이며 어디에도 링크되지 않습니다. `/reject` 한 초안은 페이지가 없습니다.

## 브리핑 정리 — 시리즈 · 태그 · 월간 정리 · RSS · 폰 설치

- **시리즈**(`social/tags.mjs` → `SERIES`): 이번 주 AX 사건 · 월간 AX 리포트 · 주요 변화 · 이번 주 정리 · 월간 정리 · AX 흐름.
  `/briefs/series/<id>`.
- **태그**: 주제·업종은 고정 목록에서만(Claude가 고르고 목록 밖은 버림), 회사·기관은 그 글이 쓴 공식 발표에서 코드가 붙임.
  `/briefs/tag/theme-<id>` · `industry-<id>` · `company-<id>`.
- 목록은 달별로 묶이고, 글마다 같은 시리즈의 이전·다음 글과 태그가 겹치는 "같이 읽기" 3편이 붙습니다.
- **월간 정리**(`social/roundup.mjs`): 매달 초, 지난달 **게시된** 브리핑이 2편 이상이면 그것들만으로 "N월 AX 정리" 1편(웹 전용).
  숫자는 브리핑에 있는 것만, 섹션마다 근거 브리핑 링크.
- **RSS**: `/briefs/feed.xml` (최근 30편) — 나중에 이메일(RSS → 메일)도 이걸로.
- **폰 설치(PWA)**: `manifest.webmanifest` · `sw.js` · `icons/`. 안드로이드 크롬은 "앱 설치" 버튼, 아이폰은 사파리 공유 → "홈 화면에 추가".
- **푸시 알림(OneSignal)**: `/briefs`의 "새 브리핑 알림"에서 주제(이번 주 AX 사건 / 월간 리포트 / 그 밖의 브리핑)를 골라 켭니다
  (주제 = OneSignal 태그 `news`·`monthly`·`other`, 앱 ID는 `social/notify-config.mjs`). `social/notify.mjs`가 인스타 게시가 끝난
  브리핑(월간 정리는 쓰인 직후)을 그 주제를 고른 사람에게 한 번씩 보냅니다(`social/notified.json`). 페이지가 사이트에 뜬 걸 확인한 뒤 보내고,
  최근 3일 것만 보냅니다. 키: GitHub Secret `ONESIGNAL_REST_KEY`. 아이폰은 홈 화면에 추가한 앱에서만 알림을 켤 수 있어요.

## AX 사건 — 공식 발표만 (매주)

회사·정부가 **직접 낸 발표**만 모아 일주일에 한 번 "이번 주 AX 사건" 스토리로 올립니다. 언론 보도·루머·집계 사이트는 쓰지 않습니다.

- **출처** (`trends/series.mjs` → `NEWS`, 피드 20개, 120일 보관): OpenAI · Anthropic · Google · Google Cloud · Microsoft(2개) · Amazon · NVIDIA ·
  Salesforce · SAP · Databricks · Snowflake · 삼성전자 · SK텔레콤의 뉴스룸·공식 블로그, 과학기술정보통신부 보도자료 ·
  EU 집행위원회 · 영국 정부 · 미국 NIST, McKinsey · Capgemini 리서치. 링크가 그 회사·기관 **자기 도메인**일 때만 받습니다(검산 `news:official`).
- **고르는 법**: AI + 기업 도입·협력·업무(회사) 또는 AI(정부·리서치)가 함께 나오는 발표만. 도입·인수·협약·정책·규제가
  위로, 소비자 제품·행사·광고는 아래로(`NEWS.rank`). 최근 14일 목록은 사이트 "AX 사건" 칸에 원문 링크와 함께 나옵니다.
- **올리는 때**: 빅 케이스가 없고, 지난 AX 사건 게시물에서 6일 넘게 지났고, 최근 7일 안에 아직 안 쓴 발표가 3건 이상일 때.
  Run workflow에서 "이번 주 AX 사건 지금 올리기"로 바로 올릴 수도 있습니다.
- **믿을 수 있게 하는 장치**:
  - 장마다 어떤 발표를 말하는지(`refs`) 적어야 통과하고(표지·확인할 점·정리 장은 예외), **출처·날짜 줄은 코드가 발표 데이터에서 찍습니다**(Claude가 쓰지 않음).
  - 숫자는 그 발표의 제목·요약·원문에 있는 것만. 금액은 원문 표기 그대로(`$5.66 billion`).
  - "OO는 ~라고 발표했어요"처럼 누가 말했는지 밝히고, 회사의 자평은 그 회사의 말로만 옮깁니다.
  - 발표문 문장(원문 포함)을 24자 넘게 그대로 옮기면 거절합니다(우리 말로 바꿔 쓰기). 사례는 칸마다 따로 봅니다.
  - 쓴 발표만 "사용함"으로 기록해, 고르지 않은 발표는 다음 주 후보로 남습니다.
- 캡션 끝에는 쓴 발표의 회사·기관 이름이 붙고, 원문 링크는 사이트에 있습니다.

## 작은 변화

매일 오늘 숫자를 어제 숫자(`trends/data/state.json`, 하루 한 장씩 60일)와 견줘 찾습니다. 첫날은 견줄 게 없어 비교형은 울리지 않습니다.

| 종류 | 언제 |
|---|---|
| 증가 | 지난주 다운로드가 평소의 1.2배 이상 (대조군과 AI 패키지 전반의 몫을 뺀 뒤 — 빅 케이스는 1.4배) |
| 증가(전반) | AI 패키지가 함께 대조군보다 1.2배 이상 오름 → 패키지마다가 아니라 한 건으로 |
| 최고치 | 역대 최고 경신, 단 이전 최고가 8주 넘게 묵었을 때 (꾸준히 크는 패키지가 매주 울리지 않게) |
| 순위 | npm·PyPI 초과 성장 1위가 바뀜, 또는 상위 3에 새로 듦 · 주제별 가장 빨리 크는 도구가 바뀜 |
| 비중 | 앱에 붙이는 모델 비중이 한 주 사이 1%p 넘게 움직임 (가장 크게 움직인 하나) |
| 새로 진입 | Hugging Face 다운로드 상위 20, 트렌딩 상위 5에 새로 든 모델 |
| 연구 | 분야별 가장 빨리 늘어난 말이 바뀜 · 한 달 치 논문 집계가 끝남 |
| 공시 | 빅테크 한 곳이 새 분기 설비투자를 공시 (넷 다 모이면 빅 케이스) |

같은 대상이 같은 날 여러 번 걸리면(예: 최고치와 급증) 큰 쪽 하나만 남깁니다. 모든 변화는 `trends/data/changes.json`에
60일 동안 남고, 사이트 탭 위 "최근 변화"에 최근 7일 것이 날짜와 함께 보입니다.

## 반복 규칙

- 같은 변화는 한 번만, **같은 대상(패키지·말·순위)은 21일 동안** 다시 초안을 만들지 않습니다. 하루 최대 1건(데이터 날짜 기준).
- `/reject` 한 것도 기록에 남아 같은 규칙이 적용됩니다 — 기록은 `social/posted.json`, 그 게시물의 `post.json` → `rejected`.
- **두 번 올리지 않습니다**: `publish.mjs` 가 올리기 전에 계정의 최근 게시물을 읽어, 같은 카드가 이미 있으면 기록만 남깁니다.
  게시는 한 번에 하나(`instagram-publish` 그룹). `/approve` 는 워크플로가 연 그대로의 승인 이슈에서만 받습니다(본문을 고친 이슈는 거절).
- 다운로드는 주 단위로 정산이 끝난 숫자, 논문은 다 지난 달만 봅니다. 하루치 몰림으로는 울리지 않습니다.

## 매번 다른 표현

인사이트마다 그릴 수 있는 데이터 모양이 있고(`trends/viz.mjs`), 모양마다 그리는 방법이 셋입니다.

| 모양 | 그리는 방법 |
|---|---|
| 흐름 | 면적 · 선 · 막대 |
| 전후 | 기울기 · 두 막대 · 화살표 숫자 |
| 비중 | 도넛 · 와플(100칸) · 띠 |
| 순위 | 막대 · 점 · 시상대 |

카드 배치도 셋(숫자 먼저 · 그림 먼저 · 문장 먼저), 표지도 둘씩(빅 케이스: 큰 숫자 · 브론즈 경보 / 묶음: 목록 · 타일 넷)
번갈아 씁니다. 같은 인사이트는 지난 두 번 초안에서 쓴 그림을 피하고, 한 게시물 안에서도 그림이 겹치지 않게 고릅니다.
무엇을 골랐는지는 `social/out/<날짜>/design.json`에 남고, 다음 초안이 그걸 보고 피합니다. 사이트(/)는 인사이트마다
첫 번째 방법으로 고정합니다.

## 스토리 — 게시물 하나에 이야기 하나

`social/story.mjs`가 게시물마다 **형식**을 고르고(지난 두 번과 겹치지 않게), Claude가 그 형식으로 **스토리**를 씁니다.
장 수는 이야기에 맞게(4~10장), 그림보다 글 위주입니다.

쓴 뒤에 **교정**을 한 번 더 거칩니다: Claude가 맞춤법·띄어쓰기·조사(숫자·영어 뒤 포함)·문장 끝·줄바꿈만 고치고,
코드가 숫자(단위 없는 1~10 제외, 부호 포함)와 장 순서·사례가 그대로인지 확인해 같을 때만 교정본을 씁니다. 두 칸 띄어쓰기, 문장부호 앞 빈칸,
괄호 짝, 세 줄 넘는 제목은 코드가 바로 걸러 냅니다.

디자인은 에디토리얼입니다(2026-10-25): 검정(#050505) 바탕 · 아이보리 글자 · 브론즈(#B8956A)는 숫자에만, 글꼴은 Pretendard 하나.
알약 배지·박스·글로우·넓은 자간 없이 키커 선과 헤어라인으로 나누고, 목록은 브론즈 번호 + 헤어라인 줄입니다.
뉴스 장에는 출처·날짜 줄(코드가 찍음), 마지막 장에는 "자세한 풀이는 브리핑에서 · data.pivoxquant.com/briefs/<폴더>".

**줄바꿈**: 쓰는 단계에서 제목은 한 줄 14자, 본문은 22자 안쪽으로 뜻 덩어리마다 끊게 하고, 제목 18자·본문 28자를 넘는 줄은
코드가 거절해 다시 쓰게 합니다. 회사 이름을 "·"로 세 곳 넘게 잇지 않고("OO 등 5곳"), "·" 뒤에서는 줄이 바뀔 수 있습니다.
숫자와 뒤 조사("36.2%로")는 같은 줄에 붙입니다.
글자 크기는 장마다 자동으로 맞춥니다(0.7~1.6배): 쓴 사람이 나눈 줄이 하나도 다시 접히지 않는 가장 큰 크기(1배 이상일 때)를 먼저 쓰고,
아니면 높이에 맞는 크기를 씁니다. 남는 공간은 위아래로 나눠 가운데에 둡니다.

| 형식 | 언제 | 흐름 (모두 사건 → 의미 → 실무 체크) |
|---|---|---|
| 월간 AX 리포트 · 업종 딥다이브 · 타임라인 | AX 새 달 숫자 | 이번 달 이야기 → 무엇이 움직였나(큰 숫자 두 장까지) → 왜 그렇게 읽히나 → IT 영역별 공식 발표와 이어 보기 → 확인할 점 → 정리 |
| 속보 · A vs B | 1위 교체 | 무슨 일 → 그 숫자 하나 → 전과 견주면 → 어느 IT 영역의 일인가 → 확인할 점 → 정리 |
| 속보 | 그 밖의 AX 빅 케이스 | |
| 이번 주 AX 사건 · AX 사건 묶어 보기 | 공식 발표 (주 1회) | 표지 → 사례 3~5건(한 장에 하나, 영역별로 묶기도) → 공통 흐름 → 확인할 점 → 정리 |
| 이번 주 정리 · 체크리스트 | 작은 변화 모음 | |
| 개념 풀이 · 퀴즈 · 타임라인 · 체크리스트 | 조용한 날 | |

- Claude는 `trends/data/insights.json`의 `facts`(AX 숫자)와 그 주의 공식 발표(제목·요약·원문)만 보고 씁니다. 슬라이드·사례·캡션·브리핑의
  모든 숫자가 거기 있는 숫자인지, 추천·전망 같은 말이 없는지, 메모가 섞이지 않았는지 코드가 검사하고(`social/claude.mjs` 한 벌),
  어긋나면 한 번 다시 쓰게 합니다.
- Claude에 닿지 않거나 두 번 다 어긋나면 카드 문장·발표 제목으로 대체 글을 만들되, **같은 검사**를 거칩니다. 못 넘으면 그날은 게시하지 않고
  초안을 지운 뒤(`util.mjs` → `dropDraft`) 사이트만 갱신하고, 이슈로 알립니다. (영어 제목이 그대로 들어간 대체 카드는 대개 못 넘습니다.)
- 결과: `social/out/<날짜>/story.json` (형식, 장, 사례, 캡션, 브리핑, 어떤 길로 썼는지 — 모델 이름은 적지 않음).

 (코드가 강제)

- 본문의 **모든 숫자는 그 게시물이 근거로 삼은 것**(카드·팩트·발표, 원문에서만 온 숫자는 `story.json` → `original_numbers`)에 있어야 합니다.
  반올림하거나 새로 계산한 숫자는 거절됩니다. 단위 없는 1~10(개수)만 예외입니다.
- **추천·매수·매도·전망·예상·급등** 같은 말은 거절됩니다. 지난 숫자만 말하고 예측하거나 권하지 않습니다.
- 출처 줄, 링크, "다운로드는 설치 횟수" 안내, 해시태그는 모델이 아니라 코드가 붙입니다.
- 모델은 `social/claude.mjs` → `MODEL` 한 곳. 부르는 길은 둘, 이 순서로 씁니다:
  - **Claude 구독** — `CLAUDE_CODE_OAUTH_TOKEN`(`claude setup-token`으로 만든 토큰)이 있으면 Claude Code CLI(`claude -p`)로. 구독 외 비용 없음, 구독 사용 한도를 같이 씀.
  - **API 키** — `ANTHROPIC_API_KEY`가 있으면 SDK로. 쓴 만큼 결제(안전 분류기가 거절하면 권장 모델로 다시 시도하는 `fallbacks: "default"` 켜 둠).
  - 둘 다 없거나 연결이 안 되면(토큰 만료 등) 대체 글로 넘어가고, 검사를 못 넘으면 그날은 게시하지 않습니다(이슈에 이유).
- 모델이 돌려준 글이 그대로 게시되므로, 본문 밖의 메모·구분선(---)이 섞이면 거절하고 다시 쓰게 합니다.

## 한 번만 하면 되는 설정

### 1. 인스타그램 토큰 (비즈니스 계정)

인스타그램 공식 API(Instagram API with Instagram Login)를 씁니다. 메타 화면 이름은 바뀔 수 있습니다.

1. [developers.facebook.com](https://developers.facebook.com) → 앱 만들기 → 사용 사례에서 **Instagram API**(인스타그램 로그인 방식) 추가.
2. 앱의 Instagram 설정에서 게시할 **비즈니스 계정을 연결**하고 권한 `instagram_business_basic`, `instagram_business_content_publish` 로 **액세스 토큰을 생성**합니다. 본인 계정에만 게시하므로 앱 검수(App Review) 없이 개발 모드로 됩니다.
3. 화면에 나오는 **인스타그램 사용자 ID**와 **토큰**을 복사합니다.
4. 토큰은 60일 동안 유효합니다. **자동 갱신**: `.github/workflows/ig-token.yml`이 매달 1·11·21일에 새 토큰을 받아 `IG_ACCESS_TOKEN` 시크릿을
   바꿔 넣습니다. 시크릿을 쓰려면 한 번만 아래 "인스타그램 토큰 자동 갱신"의 `SECRETS_PAT`를 넣어 두세요. 실패하면 이슈가 열립니다.

#### 인스타그램 토큰 자동 갱신 (한 번만)

GitHub → 오른쪽 위 프로필 → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
- 이름 `pivoxdata secrets`, 만료 최대(1년), Repository access: **Only select repositories → pivoxdata**
- Permissions → Repository permissions → **Secrets: Read and write** (나머지는 건드리지 않음) → Generate
- 나온 값을 저장소 Settings → Secrets and variables → Actions → New repository secret, 이름 **`SECRETS_PAT`** 로 저장.
  (이 값은 이 저장소의 시크릿만 바꿀 수 있습니다. 1년 뒤 만료되면 같은 방법으로 새로 넣기 — 만료되면 갱신 실패 이슈가 열립니다.)

페이스북 페이지에 연결된 계정을 Facebook 로그인으로 쓰고 있다면 저장소 변수 `IG_GRAPH_HOST` 를 `graph.facebook.com` 으로 두면 됩니다.

### 2. GitHub에 넣을 것 (저장소 Settings → Secrets and variables → Actions)

| 종류 | 이름 | 값 |
|---|---|---|
| Secret | `CLAUDE_CODE_OAUTH_TOKEN` | Claude 구독 토큰 — 컴퓨터 터미널에서 `claude setup-token` 실행 후 나오는 값 (이야기·캡션·브리핑, 권장) |
| Secret (선택) | `ANTHROPIC_API_KEY` | 구독 대신 API 키로 쓰려면 (둘 다 없으면 대체 글 — 검사를 못 넘으면 게시 없음) |
| Secret | `IG_USER_ID` | 1-3의 인스타그램 사용자 ID |
| Secret | `IG_ACCESS_TOKEN` | 1-3의 토큰 |
| Variable (선택) | `IG_GRAPH_HOST` | 기본 `graph.instagram.com` |
| Variable (선택) | `IG_API_VERSION` | 기본 `v23.0` |
| Variable (선택) | `SEC_CONTACT` | SEC가 요구하는 연락처 이메일. 기본 `support@pivoxquant.com` |

그리고 Settings → Actions → General → Workflow permissions 를 **Read and write** 로 둬야 매일 작업이 커밋하고 이슈를 열 수 있습니다.

### 3. 첫 실행

Actions → **trends daily** → Run workflow. 빅 케이스가 있거나(또는 첫 실행이면) 몇 분 뒤 `[instagram]` 이슈가 열립니다.
카드와 캡션을 보고 `/approve`.
손으로 돌릴 때(Actions → trends daily → Run workflow) "인스타그램" 칸에서 고릅니다:
- **규칙대로** — 매일 자동 실행과 같음 (빅 케이스 → 바로 게시, 작은 변화는 일주일치를 모아서)
- **이번 주 AX 사건 지금 올리기** — 최근 7일 공식 발표로 AX 사건 게시물을 지금 바로
- **테스트 초안 (승인 필요)** — 오늘 올릴 게 없어도 초안을 만들고, `/approve` 해야 게시

버튼 없이(예: 버튼 권한이 없는 세션에서): main 에 `social/request.json` 을 `{"post":"news"}` 또는 `{"post":"test"}` 로 push 하면
같은 일을 합니다. 그날 받은 데이터가 있으면 다시 받지 않고, 쓴 요청 파일은 지워집니다. 폴더 이름은 한국 날짜이고,
같은 날 두 번째 게시물은 `social/out/<날짜>-2` 에 씁니다(그날 폴더가 이미 있으면 — 승인을 기다리는 초안도 덮어쓰지 않음).

## 로컬에서

```bash
npm ci
npm run trends                      # 데이터 → 검산 → 대시보드(/)
node social/plan.mjs --dry-run       # 오늘 초안을 만들지, 무엇으로 만들지만 출력
npm run social                       # plan → story → build → render → caption → briefs
node social/publish.mjs social/out/<날짜>/post.json --dry-run   # 게시하지 않고 보낼 내용만 출력
```

`render.mjs` 는 Playwright의 Chromium을 씁니다(`npx playwright install chromium`, 또는 `CHROMIUM_PATH`).

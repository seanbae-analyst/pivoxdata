# 인스타그램 카드 — 설정과 흐름

정해진 요일이 아니라 **변화가 생겼을 때** 카드(1080×1350 캐러셀)와 캡션을 만들고, **검사를 통과하면 바로 인스타그램에 올립니다.**
큰 변화(빅 케이스)는 그날 바로, 작은 변화는 일주일치를 모아서. 올린 뒤에는 닫힌 `[게시됨]` 이슈로 기록이 남습니다.

**승인 방식으로 돌리려면** 저장소 Settings → Secrets and variables → Actions → **Variables** 탭에서
`AUTO_PUBLISH` 를 `false` 로 만드세요. 그러면 `[instagram]` 이슈가 열리고, 소유자가 `/approve` 를 달아야 올라갑니다.
Run workflow의 "테스트 초안 (승인 필요)"와, 자동 게시가 실패한 날은 늘 승인 이슈로 돌아갑니다.

```
매일 10:17 KST  trends.yml
  ├ 데이터 받기 → 검산 → 대시보드(/) 다시 만들기 + 변화 찾기 → trends/data/changes.json   (검산 실패 → 이슈)
  ├ social/plan.mjs    오늘 초안을 만들까?
  │                      · 3일 안에 잡힌, 처음 보는 빅 케이스가 있으면 → 점수가 가장 높은 것 하나
  │                      · 지난 초안 뒤 7일이 지났고 작은 변화가 3개 이상 쌓였으면 → 작은 변화 모음 (최대 5개)
  │                      · 14일 동안 아무것도 없었으면 → 요즘 숫자 묶음
  │                      · 아니면 → 사이트만 갱신하고 끝 (작은 변화는 사이트 "최근 변화"에 쌓임)
  ├ social/build.mjs   빅 케이스 카드 + 같은 주제 카드, 또는 작은 변화 카드들 → HTML (그림·배치는 지난 두 번과 다르게)
  ├ social/render.mjs  카드 → social/out/<날짜>/01.png …
  ├ social/caption.mjs Claude가 캡션 본문 작성 → 코드가 숫자·금지어 검사 (2번 실패하면 템플릿 캡션)
  ├ main에 커밋 → Vercel 배포 (이미지가 data.pivoxquant.com/social/out/… 에 공개됨)
  ├ social/publish.mjs 인스타그램에 바로 게시 → 닫힌 "[게시됨] <날짜> …" 이슈로 기록 (카드·캡션·링크)
  └ (AUTO_PUBLISH=false · 테스트 초안 · 게시 실패일 때) "[instagram] <날짜> …" 승인 이슈
     소유자가 /approve → social-publish.yml → 게시 → 링크 남기고 닫음 · /reject → 게시하지 않고 닫음
```

## AX 사건 — 공식 발표만 (매주)

회사·정부가 **직접 낸 발표**만 모아 일주일에 한 번 "이번 주 AX 사건" 스토리로 올립니다. 언론 보도·루머·집계 사이트는 쓰지 않습니다.

- **출처** (`trends/series.mjs` → `NEWS`): OpenAI · Anthropic · Google · Google Cloud · Microsoft · Amazon · NVIDIA ·
  Salesforce · SAP · Databricks · Snowflake · 삼성전자 · SK텔레콤의 뉴스룸·공식 블로그, 과학기술정보통신부 보도자료 ·
  EU 집행위원회 · 영국 정부 · 미국 NIST, McKinsey 리서치. 링크가 그 회사·기관 **자기 도메인**일 때만 받습니다(검산 `news:official`).
- **고르는 법**: AI + 기업 도입·협력·업무(회사) 또는 AI(정부·리서치)가 함께 나오는 발표만. 도입·인수·협약·정책·규제가
  위로, 소비자 제품·행사·광고는 아래로(`NEWS.rank`). 최근 14일 목록은 사이트 "AX 사건" 칸에 원문 링크와 함께 나옵니다.
- **올리는 때**: 빅 케이스가 없고, 지난 AX 사건 게시물에서 6일 넘게 지났고, 최근 7일 안에 아직 안 쓴 발표가 3건 이상일 때.
  Run workflow에서 "이번 주 AX 사건 지금 올리기"로 바로 올릴 수도 있습니다.
- **믿을 수 있게 하는 장치**:
  - 장마다 어떤 발표를 말하는지(`refs`) 적어야 통과하고, **출처·날짜 줄은 코드가 발표 데이터에서 찍습니다**(Claude가 쓰지 않음).
  - 숫자는 그 발표의 제목·요약에 있는 것만. 금액은 원문 표기 그대로(`$5.66 billion`).
  - "OO는 ~라고 발표했어요"처럼 누가 말했는지 밝히고, 회사의 자평은 그 회사의 말로만 옮깁니다.
  - 발표문 문장을 24자 넘게 그대로 옮기면 거절합니다(우리 말로 바꿔 쓰기).
  - 쓴 발표만 "사용함"으로 기록해, 고르지 않은 발표는 다음 주 후보로 남습니다.
- 캡션 끝에는 쓴 발표의 회사·기관 이름이 붙고, 원문 링크는 사이트에 있습니다.

## 작은 변화

매일 오늘 숫자를 어제 숫자(`trends/data/state.json`, 하루 한 장씩 60일)와 견줘 찾습니다. 첫날은 견줄 게 없어 비교형은 울리지 않습니다.

| 종류 | 언제 |
|---|---|
| 증가 | 지난주 다운로드가 평소의 1.2배 이상 (대조군과 AI 패키지 전반의 몫을 뺀 뒤 — 빅 케이스는 1.4배) |
| 증가(전반) | AI 패키지가 함께 대조군보다 1.2배 이상 오름 → 패키지마다가 아니라 한 건으로 |
| 최고치 | 역대 최고 경신, 단 이전 최고가 8주 넘게 묵었을 때 (꾸준히 크는 패키지가 매주 울리지 않게) |
| 순위 | npm·PyPI 초과 성장 1위가 바뀜, 또는 상위 3에 새로 듦 · 주제별 가장 빨리 크는 도구가 바뀜 |
| 비중 | 앱에 붙이는 모델 비중이 한 주 사이 1%p 넘게 움직임 (가장 크게 움직인 하나) |
| 새로 진입 | Hugging Face 다운로드 상위 20, 트렌딩 상위 5에 새로 든 모델 |
| 연구 | 분야별 가장 빨리 늘어난 말이 바뀜 · 한 달 치 논문 집계가 끝남 |
| 공시 | 빅테크 한 곳이 새 분기 설비투자를 공시 (넷 다 모이면 빅 케이스) |

같은 대상이 같은 날 여러 번 걸리면(예: 최고치와 급증) 큰 쪽 하나만 남깁니다. 모든 변화는 `trends/data/changes.json`에
60일 동안 남고, 사이트 탭 위 "최근 변화"에 최근 7일 것이 날짜와 함께 보입니다.

## 반복 규칙

- 같은 변화는 한 번만, **같은 대상(패키지·말·순위)은 21일 동안** 다시 초안을 만들지 않습니다. 하루 최대 1건.
- `/reject` 한 것도 기록에 남아 같은 규칙이 적용됩니다 — 기록은 `social/posted.json`.
- 다운로드는 주 단위로 정산이 끝난 숫자, 논문은 다 지난 달만 봅니다. 하루치 몰림으로는 울리지 않습니다.

인사이트마다 그릴 수 있는 데이터 모양이 있고(`trends/viz.mjs`), 모양마다 그리는 방법이 셋입니다.

| 모양 | 그리는 방법 |
|---|---|
| 흐름 | 면적 · 선 · 막대 |
| 전후 | 기울기 · 두 막대 · 화살표 숫자 |
| 비중 | 도넛 · 와플(100칸) · 띠 |
| 순위 | 막대 · 점 · 시상대 |

카드 배치도 셋(숫자 먼저 · 그림 먼저 · 문장 먼저), 표지도 둘씩(빅 케이스: 큰 숫자 · 브론즈 경보 / 묶음: 목록 · 타일 넷)
번갈아 씁니다. 같은 인사이트는 지난 두 번 초안에서 쓴 그림을 피하고, 한 게시물 안에서도 그림이 겹치지 않게 고릅니다.
무엇을 골랐는지는 `social/out/<날짜>/design.json`에 남고, 다음 초안이 그걸 보고 피합니다. 사이트(/)는 인사이트마다
첫 번째 방법으로 고정합니다.

## 스토리 — 게시물 하나에 이야기 하나

`social/story.mjs`가 게시물마다 **형식**을 고르고(지난 두 번과 겹치지 않게), Claude가 그 형식으로 **스토리**를 씁니다.
장 수는 이야기에 맞게(4~12장), 그림보다 글 위주입니다.

쓴 뒤에 **교정**을 한 번 더 거칩니다: Claude가 맞춤법·띄어쓰기·조사(숫자·영어 뒤 포함)·문장 끝·줄바꿈만 고치고,
코드가 숫자(1~10 제외)와 장 순서가 그대로인지 확인해 같을 때만 교정본을 씁니다. 두 칸 띄어쓰기, 문장부호 앞 빈칸,
괄호 짝, 세 줄 넘는 제목은 코드가 바로 걸러 냅니다.

디자인은 PivoxQuant와 같습니다: 검정(#050505) 바탕 · 아이보리 글자 · 브론즈(#B8956A) 숫자, 글꼴은 Pretendard 하나,
카드 모서리 14px, 글로우·넓은 자간 없음. 빅 케이스 표지는 위쪽 브론즈 띠로 구분합니다.
글자 크기는 장마다 자동으로 맞춥니다(0.7~1.6배): 아래가 비지 않을 만큼 키우고, 넘치면 줄입니다. 1.6배로도 남는 공간은
위아래로 나눠 가운데에 둡니다. 숫자와 뒤 조사("36.2%로")는 같은 줄에 붙이고, 길어서 접히는 줄은 고르게 나눕니다.

| 형식 | 언제 | 흐름 |
|---|---|---|
| 월간 AX 리포트 · 업종 딥다이브 · 타임라인 | AX 새 달 숫자 | 요약 → 전체 → 업종 → 규모 → 기업이 고르는 AI → 개발 현장 → 정리 |
| 속보 · A vs B | 1위 교체 | 무슨 일 → 숫자 → 전과 비교 → 의미 → 정리 |
| 속보 | 그 밖의 빅 케이스 | |
| 이번 주 정리 · 체크리스트 | 작은 변화 모음 | |
| 도구 가이드 · A vs B · 퀴즈 | 누가 앞서나 | |
| 개념 풀이 · 퀴즈 · 타임라인 · 체크리스트 | 조용한 날 | |

- Claude는 `trends/data/insights.json`의 `facts`(AX 숫자, 레이스, 레이더)만 보고 씁니다. 슬라이드와 캡션의 모든 숫자가
  팩트에 있는 숫자인지, 추천·전망 같은 말이 없는지, 메모가 섞이지 않았는지 코드가 검사하고, 어긋나면 한 번 다시 쓰게 합니다.
- Claude에 닿지 않거나 두 번 다 어긋나면, 그날 카드 문장으로 만든 단순한 스토리로 올립니다(게시물이 빠지지 않게).
- 결과: `social/out/<날짜>/story.json` (형식, 장, 캡션, 누가 썼는지).

 (코드가 강제)

- 본문의 **모든 숫자는 그 게시물 카드에 적힌 숫자**여야 합니다. 반올림하거나 새로 계산한 숫자는 거절됩니다.
- **추천·매수·매도·전망·예상·급등** 같은 말은 거절됩니다. 지난 숫자만 말하고 예측하거나 권하지 않습니다.
- 출처 줄, 링크, "다운로드는 설치 횟수" 안내, 해시태그는 모델이 아니라 코드가 붙입니다.
- 모델: `claude-opus-5-5`. 부르는 길은 둘, 이 순서로 씁니다:
  - **Claude 구독** — `CLAUDE_CODE_OAUTH_TOKEN`(`claude setup-token`으로 만든 토큰)이 있으면 Claude Code CLI(`claude -p`)로. 구독 외 비용 없음, 구독 사용 한도를 같이 씀.
  - **API 키** — `ANTHROPIC_API_KEY`가 있으면 SDK로. 쓴 만큼 결제(안전 분류기가 거절하면 권장 모델로 다시 시도하는 `fallbacks: "default"` 켜 둠).
  - 둘 다 없거나 연결이 안 되면(토큰 만료 등) 템플릿 캡션으로 넘어가고, 승인 이슈에 이유가 적힙니다.
- 모델이 돌려준 글이 그대로 게시되므로, 본문 밖의 메모·구분선(---)이 섞이면 거절하고 다시 쓰게 합니다.

## 한 번만 하면 되는 설정

### 1. 인스타그램 토큰 (비즈니스 계정)

인스타그램 공식 API(Instagram API with Instagram Login)를 씁니다. 메타 화면 이름은 바뀔 수 있습니다.

1. [developers.facebook.com](https://developers.facebook.com) → 앱 만들기 → 사용 사례에서 **Instagram API**(인스타그램 로그인 방식) 추가.
2. 앱의 Instagram 설정에서 게시할 **비즈니스 계정을 연결**하고 권한 `instagram_business_basic`, `instagram_business_content_publish` 로 **액세스 토큰을 생성**합니다. 본인 계정에만 게시하므로 앱 검수(App Review) 없이 개발 모드로 됩니다.
3. 화면에 나오는 **인스타그램 사용자 ID**와 **토큰**을 복사합니다.
4. 토큰은 60일 동안 유효합니다. 만료 전에 아래 주소로 연장하세요(새 토큰이 나오면 GitHub 시크릿을 바꿔 넣기).
   `https://graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token&access_token=<토큰>`

페이스북 페이지에 연결된 계정을 Facebook 로그인으로 쓰고 있다면 저장소 변수 `IG_GRAPH_HOST` 를 `graph.facebook.com` 으로 두면 됩니다.

### 2. GitHub에 넣을 것 (저장소 Settings → Secrets and variables → Actions)

| 종류 | 이름 | 값 |
|---|---|---|
| Secret | `CLAUDE_CODE_OAUTH_TOKEN` | Claude 구독 토큰 — 컴퓨터 터미널에서 `claude setup-token` 실행 후 나오는 값 (캡션용, 권장) |
| Secret (선택) | `ANTHROPIC_API_KEY` | 구독 대신 API 키로 쓰려면 (둘 다 없으면 템플릿 캡션) |
| Secret | `IG_USER_ID` | 1-3의 인스타그램 사용자 ID |
| Secret | `IG_ACCESS_TOKEN` | 1-3의 토큰 |
| Variable (선택) | `IG_GRAPH_HOST` | 기본 `graph.instagram.com` |
| Variable (선택) | `IG_API_VERSION` | 기본 `v23.0` |
| Variable (선택) | `SEC_CONTACT` | SEC가 요구하는 연락처 이메일. 기본 `support@pivoxquant.com` |

그리고 Settings → Actions → General → Workflow permissions 를 **Read and write** 로 둬야 매일 작업이 커밋하고 이슈를 열 수 있습니다.

### 3. 첫 실행

Actions → **trends daily** → Run workflow. 빅 케이스가 있거나(또는 첫 실행이면) 몇 분 뒤 `[instagram]` 이슈가 열립니다.
카드와 캡션을 보고 `/approve`.
손으로 돌릴 때(Actions → trends daily → Run workflow) "인스타그램" 칸에서 고릅니다:
- **규칙대로** — 매일 자동 실행과 같음 (빅 케이스 → 바로 게시, 작은 변화는 일주일치를 모아서)
- **누가 앞서나 지금 올리기** — 분야별 1위 레이스 캐러셀을 지금 바로 게시
- **테스트 초안 (승인 필요)** — 오늘 올릴 게 없어도 초안을 만들고, `/approve` 해야 게시

## 2026-10-25 — IT 컨설팅 관점의 AX로 정리

### 1. 주제: 기술 분야 → IT 컨설팅 관점의 AX
- "it consulting이 주제였자나", "erp나 이런것도 넣어주던가",
  "주제를 뭐 양자 이런식으로 나눠야하나 어차피 ax로 가기로 했으니까 인스타에도 ax 주제만 올림".
- 결정: 사이트 탭을 AI·양자·로보틱스·비전·보안·시스템에서 **기업 도입률 / IT 영역별 발표** 둘로 바꿨다.
  IT 영역은 7개(ERP·백오피스, CRM·고객, 클라우드·인프라, 데이터·분석, 업무 도구, 보안·규제, AI 에이전트)이고,
  공식 발표를 정규식으로 나눠 센다(`trends/series.mjs` → `DOMAINS`). arXiv 비AI 분야와 HF 태스크는 수집에서 뺐다.
- 소비자 제품 발표(예: 통신사의 스마트폰 출시)는 IT 영역 집계에서 빠진다(`NEWS.rank` 점수 < 0).

### 2. 사이트: 보고서처럼, 장치 없이
- "누가앞서나 이런거말고..ㅋㅋ너무 짜치자나화면구성이..", "너무 ai 느낌나지 않니..", "폰으로보니까 넘 별론데".
- 결정: "누가 앞서나"·"빅 케이스"를 첫 화면에서 뺐다. KPI 줄 → 최근 변화 → AX 브리핑 → 공식 발표 → 지표 → 용어 → 근거 데이터.
  알약 배지·박스 대신 헤어라인, 브론즈는 숫자와 선택 상태에만.
  "그 전 30일 대비" 비교는 수집 시작(`news.json` → `since`) 뒤 60일이 지나야 보인다. 수집 초기에 늘어난 것처럼 보이는 걸 막기 위해서다.
- 폰: "넘어가지도 않고 그냥 내려가네" → 아래 탭 바(홈·브리핑·사건), 카드 줄은 가로 스와이프, 용어 풀이는 접기.

### 3. 인스타 카드: 같은 방향, 줄바꿈 잘
- "인스타 카드도 같은 방향으로 바꿔줘 그리고 이제 it 컨설팅 같은 내용들로 올려줘라", "줄바꿈잘해라",
  "문법이나 줄바꿈 이런거 잘 해서 올리고 항상".
- 결정 (PR #44):
  - 카드 CSS를 에디토리얼로 바꿨다(키커 선, 평범한 배지, 헤어라인 목록, 브론즈 숫자).
  - Claude 역할을 "IT 컨설팅 리서치 데스크"로 바꿨다. 형식에 IT 영역 묶음(`newstheme`)과 "IT 컨설팅 관점에서 확인할 점" 장을 넣었다.
  - 줄 폭은 제목 14자·본문 22자를 목표로 하고, 18자·28자를 넘으면 다시 쓰게 했다.
  - "·" 뒤에서 줄이 바뀔 수 있게 했고, 쓴 사람이 나눈 줄은 다시 접히지 않는 크기로 맞춘다.
  - 시리즈 이름 "빅 케이스"는 "주요 변화"로 바꿨다.
- 이유: 카드가 좁아 긴 줄이 아무 데서나 접히면 문장이 깨져 보인다.
  수를 정해 두고 코드가 거절해야 매번 지켜진다(프롬프트만으로는 안 지켜졌다).

### 4. 이미 올린 것은 그대로
- "기존에 올린건 냅둘거임", "전꺼지는 채우지말고 앞으로 올라올때마다 어떻게 잘 정리할건지".
- 결정: 이미 게시된 인스타 게시물과 브리핑은 다시 만들지 않는다.
  지난 게시물에 브리핑을 거슬러 채우지 않는다. 새 규칙은 다음 게시물부터 적용된다.

### 5. 기존 리서치 데이터는 웹에 남김
- "기존 리서치 내용은 그러면 올려둬야겠지 웹과 앱에도".
- 결정: npm·PyPI·arXiv·Hugging Face·SEC·레이스 데이터는 사이트 "근거 데이터"에 남는다(설치한 앱도 같은 사이트).
  인스타에는 올리지 않는다(`AX_TOPICS`).

## 2026-10-24 ~ 25 — 카드는 짧게, 풀이는 웹, 공식 발표만

### 6. 카드는 간단히, 풀이는 웹 브리핑
- "인스타카드에는 간단하게만 올리고 풀어서는 해당 내용을 웹에 올리는거지",
  "주기적으로 리서치 내용 좀더 풀어서 웹사이트에 반영시키는게 좋을듯".
- 결정: 게시물마다 `story.json` → `article`(리드 · 섹션 3~8개 · 정리)을 같은 검사로 만들고,
  `social/briefs.mjs` 가 `/briefs/<슬롯>` 과 목록·시리즈·태그·RSS(`/briefs/feed.xml`)를 만든다.
  매달 초 지난달 브리핑이 2편 이상이면 "N월 AX 정리"를 웹에만 올린다(`social/roundup.mjs`).

### 7. AX 사건 — 공식 발표만, 출처와 날짜
- "이거는 뭔가 큰 그거를 파악하기 힘들잖아 사건사고나", "사건 넣어도 좋아 다해줘 공신력있게".
- 결정: 회사·정부·기관 뉴스룸·보도자료 RSS 20개(`NEWS`), 자기 도메인 링크만 받는다(검산 `news:official`).
  일주일에 한 번 "이번 주 AX 사건"을 올린다(지난 사건 게시물에서 6일 넘게 지났고, 7일 안에 안 쓴 발표가 3건 이상일 때).
  출처·날짜 줄은 코드가 찍는다.
- 첫 게시: 2026-10-25, https://www.instagram.com/p/De6FGlbHLJo/ · `/briefs/2026-10-25-2`.

### 8. 폰 설치와 알림
- "이것도 폰에 설치가능하게 해서", "알림으로? 지금 올라왔어요 트렌드 이런식으로".
- 결정: PWA(`manifest.webmanifest`, `sw.js`, `icons/`)와 OneSignal 웹 푸시를 붙였다.
  주제(AX 사건 / 월간 리포트 / 그 밖의 브리핑)는 태그로 고른다.
  `social/notify.mjs` 가 게시된 브리핑을 한 번씩, 최근 3일 것만, 페이지가 뜬 뒤 보낸다. 앱 ID는 `social/notify-config.mjs`.
- 로그인: "pivoxdata는 로그인 기능이 필요없나" → "일단은 두자". 이메일 구독도 보류.

### 9. 인스타 토큰 자동 갱신
- "인스타 토큰 자동 갱신도 붙여줘".
- 결정: `ig-token.yml` 이 10일마다 토큰을 갱신해 `IG_ACCESS_TOKEN` 시크릿에 다시 쓴다(소유자가 넣은 `SECRETS_PAT` 사용).
  2026-10-25 첫 실행으로 2026-12-23까지 유효해졌다.

### 10. 일하는 방식
- "너가직접해그런거", "결과 나오면 알려줘", "올라오면 바로 알려줘", "한국어로답해라", "속도좀 올려줘라".
- 결정: 버튼(`workflow_dispatch`)이 이 세션에서 403이라, 게시 요청은 `social/request.json` push로 한다.
  게시·배포 결과를 직접 확인해서 한국어로 보고한다.
  키·토큰은 소유자가 GitHub Secrets 에 직접 넣는다. 채팅으로 받지 않는다.

## 2026-10-25 (저녁) — 폰은 페이지 넘김

### 11. 폰: 위아래 스크롤 대신 페이지 넘김
- "아래로 스크롤하는 형식이 난 맘에 안 듦 모바일에서 봤을 때 페이지를 넘겨야하는 형식이 나을 것 같은데".
- 결정: 폰(640px 이하)에서는 홈과 브리핑 목록을 옆으로 넘기는 페이지로 보여 준다(`pager.js`).
  - 차례는 요약 · 브리핑 · 도입률 · IT 영역 · 변화 · 발표 · 용어 · 근거이고, 위에 쪽 막대를 둔다.
  - 지표 카드는 한 쪽에 한 장이다.
  - 목록(발표·용어·브리핑)은 그 화면에 들어가는 만큼씩 코드가 재서 나눈다.
  - 표가 긴 근거 데이터만 위아래로 읽는 화면(`?scroll=1`)으로 연다.
  - 브리핑 글은 원래 넘기는 덱이다. 데스크톱은 그대로 둔다.
- 이유: 앱처럼 한 화면에 한 가지만 보이게 하려고. 인스타 캐러셀과 같은 손동작이다.

### 12. 메뉴는 하나만 — 위 차례 줄을 뺌
- "위에도 있고 아래에도 있고 이게 뭐노" — 위에 차례 줄(요약·브리핑·도입률…)과 아래 탭 바(홈·브리핑·사건·용어)가 함께 있었다.
- 결정: 움직이는 길은 아래 탭 바 하나로 둔다. 위에는 PivoxData 이름과 지금 위치("도입률 2/5")만 둔다.
  그 밖의 쪽은 옆으로 넘겨서 간다.

### 13. 시각자료는 분명하게, 화면은 다시 짜기
- "시각자료로 애매하게 한 건 뭐냐.. UI UX 디자인 좀 잘해 봐.. 너무 실망이다".
- 무엇이 애매했나: 차트에 축·단위·기준이 없었다. 막대는 갈색 두 톤이라 구분이 안 됐다(재 보니 색 차이 ΔE 6.9).
  그림이 쪽 아래에 작게 떠 있었고, 큰 숫자·소제목·설명이 같은 말을 세 번 했다.
  IT 영역 카드 7장은 같은 설명 문장을 반복했다.
- 결정:
  - 카드 차트는 `cardfig.js`가 화면 크기에 맞춰 그리고, 폰에서는 그 쪽의 남는 자리를 채운다.
  - 차트 종류는 내용에 맞춘다.
    - 도입률 추이: 축이 있는 선 차트에 1년 전·지금 표시.
    - AI 회사별·규모별: 1년 전 → 지금(덤벨).
    - 업종별: 막대에 전체 평균 기준선.
    - IT 영역: 한눈에 보는 막대 1장 + 영역마다 발표한 곳 막대와 최근 발표 3건(원문 링크).
  - 카드가 말하는 하나만 브론즈, 나머지는 회색으로 한다. 값은 글자색으로 쓰고, 선이 글자를 가르지 않게 한다.
  - 폰 첫 쪽: 숫자 4개(누르면 해당 쪽), 새 브리핑, 설치 안내.
  - '사건' 쪽은 지표 변화와 공식 발표를 한 흐름으로 묶었다.
  - 쪽이 좁으면 덜 중요한 것부터 접는다.
